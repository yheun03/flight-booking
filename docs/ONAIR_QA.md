## 실제 브라우저 검사

인앱 Chromium과 Google Chrome에서 가상 정보만 입력했습니다.

- 편도·성인 1인·도쿄: 검색 → 라이트 → 빈 탑승객 오류 → 가상 회원 불러오기 → 카드 결제 실패/재시도/성공 → 좌석 1B → 기내식 미제공 → 체크인 → DEMO 탑승권을 직접 확인했습니다.
- 왕복·성인 2인·파리: 양 구간 라이트 선택 → 두 가상 탑승객 → 마일리지 부족 표시 → 충전 → 160,000M + 448,000원 세금 결제 → 예약 복원을 확인했습니다.
- 파리 좌석: 가는 편 1B/1C, 오는 편 2A/2B. 두 번째 탑승객에서 첫 사람의 같은 구간 좌석 선택 불가를 확인했습니다.
- 파리 기내식: 가는 편 첫 사람 과일식, 두 번째 사람 채식. 오는 편에는 선택이 복사되지 않는 것을 확인했습니다.
- 첫 사람만 체크인했을 때 탑승권 1개, 두 번째 사람까지 체크인했을 때 탑승권 2개임을 확인했습니다. 오는 편은 체크인 전으로 남았습니다.
- 체크인 전 탑승권 링크는 체크인 화면으로 안내했습니다. 초기화 후 `/payment`는 검색 화면으로, `/boarding-pass/`는 빈 나의 예약 화면으로 안내했습니다.
- 모바일 390×844: 홈·검색·운임 선택·탑승객·결제 단계, 단일 열, 하단 주요 버튼, 페이지 가로 넘침 없음을 확인했습니다. 좌석 지도는 컨테이너 약 328px / 내용 약 530px로 필요한 가로 스크롤을 유지했습니다.
- PC 1440×1000: 홈·예약 요약을 포함한 레이아웃과 페이지 가로 넘침 없음을 확인했습니다.
- 기본값과 다른 11월 15일을 달력에서 선택해 검색했습니다. 뒤로 가기·새로고침 후 운임을 플렉스로 변경했을 때 총액 275,000원으로 재계산되고 가상 탑승객 MINJUN이 유지됐습니다. 특정 날짜에만 운항하는 구현은 아닙니다.
- Drawer 닫기/Escape 후 트리거 포커스 복귀, 모달 Shift+Tab 순환, Select ArrowDown/Enter 선택을 확인했습니다. 폼 입력 오류는 label과 aria-describedby로 연결했습니다.
- 데모 데이터 초기화의 확인 모달과 초기화 후 선행 상태 가드가 동작했습니다.
- 서버 body Teleport 및 직접 URL 리다이렉트 때 발생했던 hydration 경고를 수정했습니다. 수정 뒤 새로고침·직접 접근에서는 새 경고가 추가되지 않았습니다.

## 인쇄 확인

Google Chrome의 실제 시스템 인쇄 미리보기에서 PDF로 저장 모드의 2인 탑승권이 2쪽으로 생성되는 것을 확인했습니다. PDF 미리보기 접근성 정보에서 첫 쪽 KIM MINJUN/1B, 둘째 쪽 LEE SEOYEON/1C 및 각 코드·하단 DEMO 문구가 포함됨을 확인했습니다. 첫 쪽은 화면으로도 전체 테두리와 하단 문구가 한 장 안에 들어가 잘리지 않는 것을 확인했습니다. A4와 페이지별 강제 나눔 스타일을 적용했습니다.

예약 확인서는 별도 문서 화면으로 구성했고 인쇄 호출까지 실행했습니다. 예약 확인서의 최종 PDF 저장, 둘째 탑승권 페이지의 별도 시각 캡처, 실제 프린터 출력은 실행하지 않았습니다. 탑승권 PDF 파일을 디스크에 저장하는 마지막 단계도 실행하지 않았습니다. 인앱 브라우저에서 인쇄 호출은 시스템 대화상자 제어 제약이 있어 Chrome으로 검수했습니다.

## 명령 실행 결과

- `npm run test:onair`: 9개 시나리오 통과
- `npm run build`: 성공, 146개 경로 사전 렌더링
- `npm run generate`: 성공, 146개 경로 사전 렌더링 및 `.output/public` 생성
- 생성된 정적 결과물을 별도 로컬 HTTP 서버에서 열어 홈 → 검색 결과 및 `/flights/` 새로고침을 확인했습니다. 디렉터리 경로의 trailing slash에서도 상태 가드와 단계 4개 표시를 확인했으며, 최종 정적 서버 URL의 경고/오류 로그는 없었습니다.

검수 환경의 실제 Node는 24.19.0, Nuxt는 설치된 3.21.11입니다. 프로젝트가 원래 선언한 Node 20~22 범위와 의존성 버전 범위는 유지했습니다. `.nvmrc`에는 권장 Node 22를 기록했습니다. Node 22 환경에서 명령을 재실행하지는 않았습니다.

기존 대형 관리자/그리드 번들 때문에 Rollup 청크 크기 경고가 발생합니다. 관련 없는 의존성 교체나 관리자 코드 분리는 하지 않았습니다.
